## Design Context

### Users
The roadmap owner and engineering/review contributors use this local tracker to decide what remains, what can start, what depends on other work and which acceptance requires a named external owner. This context comes from the creator's product vision and explicit tracking requests in this chat.

### Brand Personality
Clear, accountable, calm. Counts must support confidence through evidence; completed implementation packets must never imply product or release completion.

### Aesthetic Direction
Preserve the existing DeclarAI tracker typography, light theme, wine/teal palette and expandable record layout. This change clarifies planning and navigation; it does not redesign the brand or select new fonts.

### Design Principles
- Show remaining tasks before delivery history and keep their denominators explicit.
- Derive readiness from specific task dependencies; reserve blocked for an explicit impediment and resolution owner.
- Keep priority, owner, next action and acceptance visible without requiring technical log reading.
- Preserve outcome, implementation, qualification, release and customer acceptance as separate evidence states.
- Support semantic controls and keyboard navigation; report generated-source/isolated-JS checks separately from rendered or assistive-technology validation.
