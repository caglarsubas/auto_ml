## Build and installation boundary

The ingress uses [NGINX 1.30.5](https://nginx.org/en/download.html), with an exact trusted local upstream image and a captured configuration/entrypoint receipt. The qualified public multi-platform dependency is `nginx:1.30.5-alpine@sha256:0985e772fb9f729e6fa0980da05fca5d9c468e870eed43071545afa9d2e27d94`. Acquisition/build is separate from runtime; it requires the installation's approved dependency/trust procedure. The dependency's filesystem is trusted input, not an arbitrary-image sanitizer, signed attestation or reproducible binary build.

```sh
docker pull nginx:1.30.5-alpine@sha256:0985e772fb9f729e6fa0980da05fca5d9c468e870eed43071545afa9d2e27d94
python scripts/private_ingress_package.py build \
  --base-image "$(docker image inspect nginx:1.30.5-alpine@sha256:0985e772fb9f729e6fa0980da05fca5d9c468e870eed43071545afa9d2e27d94 --format '{{.Id}}')" \
  --tag declarai-private-ingress:reviewed \
  --authority api.customer.example:8443
```

Use a fresh, unique owned tag for each build. The build receipt records the exact native image/base IDs, architecture, declared authority/body limit and captured file hashes. Execution references its exact `sha256:` image ID. `context --authority ... DESTINATION` also creates a new, allowlisted build context; it contains no certificates, secrets, datasets or environment files. The build verifies the exact NGINX version and uses a networkless build step. This packet does not add the ingress image to P29's application-specific offline importer; a complete verified multi-image handoff remains open.

The authority must be a lowercase ASCII DNS name with an optional explicit public port. Default port 443 permits the standard absent/explicit `:443` Host forms; other ports require that exact authority. The baked configuration has no environment templates or caller-supplied commands. Changing authority or upload ceiling requires another reviewed image. Configure Django's existing private `DJANGO_ALLOWED_HOSTS` with the hostname, `DECLARAI_ALLOWED_ORIGINS` with approved HTTPS origins, and `DJANGO_TRUST_PROXY_TLS=true` as in P29.

Compose combines `docker-compose.private-api.yml` and `docker-compose.private-ingress.yml`. Set the existing P29 selectors, plus `DECLARAI_PRIVATE_INGRESS_IMAGE`, `DECLARAI_PRIVATE_TLS_DIRECTORY` and a separate external `DECLARAI_PRIVATE_EDGE_NETWORK`. The approved certificate directory contains `tls.crt` and `tls.key`, readable by UID/GID 10001. The private key must be owned by UID 10001 with mode 0400; symlinked certificate files are rejected. Missing/malformed/mismatched certificates, an incorrect image version, root identity or extra command arguments block listening. Certificate validity, names and chain trust are also enforced by clients; customer issuance, renewal/rotation and outage procedures remain operator responsibilities.

The container listens on 8443; `DECLARAI_PRIVATE_TLS_BIND`/`DECLARAI_PRIVATE_TLS_PORT` select the host binding, defaulting to loopback/8443. Publish a customer-approved binding matching the baked public authority and certificate. No port 80 listener/redirect, automatic certificate acquisition or public exposure is configured. Only this ingress gets the edge network; it does not join the PostgreSQL/Redis network. It mounts the dedicated API socket read-only and its own certificate directory read-only, without API secrets, artifact storage, host Docker socket or source mounts. UID/GID 10001, a read-only root, no capabilities/new privileges, one CPU, 256 MiB memory, 32 processes and a 256 MiB tmpfs are explicit bounds, not capacity promises.

## HTTP and data controls

Unknown SNI fails TLS; an unapproved Host is rejected before proxying. Malformed Host syntax receives NGINX's native 400; valid but undeclared authority receives 421. Only `/api/` and `/media/` proxy to the fixed Unix socket. Other paths, including `/admin/`, return 404. Media always passes through current Django session/project authorization; there is no filesystem alias or upstream acceleration redirect.

The proxy disables inherited request-header forwarding, admits explicit end-to-end headers needed for sessions, CSRF, bearer authentication, content types and conditional/range requests, and supplies its own canonical Host/HTTPS headers. Incoming forwarding, acceleration and hop-by-hop controls are omitted. NGINX owns upstream message framing so both fixed-length and admitted chunked uploads work. It does not establish per-client Django audit/throttle attribution: the existing application sees its Unix-socket peer, and that separate limitation remains open.

[Request buffering](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_request_buffering) keeps an incomplete upload from occupying the single synchronous API worker. The default ceiling is 50 MiB, configurable from 1 through 64 MiB at build time. Buffered bodies and all native temp paths use the bounded tmpfs; no persistent spool volume is provided. Space exhaustion/concurrent upload capacity is not qualified. Responses are buffered in bounded memory without proxy temp files/caching; upstream retries and acceleration overrides are disabled. Header/body/idle/upstream waits are bounded. Access logging is disabled and NGINX's error level is critical to avoid storing request URLs, cookies or bodies. This does not constitute comprehensive application-log, retention or egress governance. TLS 1.2/1.3 and host-scoped HSTS are configured; no blanket jurisdiction-specific cryptographic claim is made.
