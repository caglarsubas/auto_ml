# Stable protected private secret capture (P48)

Private Django, PostgreSQL and broker configuration previously accepted ordinary readable credential files without checking their link count, private modes or content consistency. `_secret(..., private=True)` now requires an absolute regular single-link file, mode 0400 or 0600 and 1–4096 bytes. It opens without following the final symlink and without blocking on a FIFO, reads at most 4097 bytes twice through the same descriptor, and compares bytes and descriptor identity/size/mode/ownership/link/timestamp metadata before accepting a single-line UTF-8 value. Resources close on every outcome. Failure diagnostics suppress underlying exceptions and never interpolate credential values or source paths.

Timestamp precision alone is insufficient, as [Python's stat documentation](https://docs.python.org/3/library/os.html#os.stat_result) explains. A local same-size rewrite preserved both timestamps; this initial failure is retained. Repeated byte comparison rejects inconsistent content even when timestamps appear unchanged. These checks establish an observed stable capture; trusted private delivery and filesystem custody remain required. Installation ownership, ancestor/ACL constraints and read-only mounts retain their existing independent checks. Generic private parsing does not claim to authenticate a filesystem owner or perform rotation.

Private `_FILE` inputs for Django's signing key, the PostgreSQL application password and the broker URL all use this boundary. Explicit development file/direct-value behavior remains supported. Existing private direct values retain their explicit contract; governed installation plans continue selecting protected files. Weak private file deliveries now block with an actionable configuration error. No existing root, credential or saved plan is rewritten or migrated, and captured values do not implicitly rotate a running process.

Unit qualification covers private modes, single-link/regular/absolute requirements, bounded UTF-8/single-line values, file/content/metadata changes during capture including coarse timestamps, static trace diagnostics, actual runtime/broker configuration entrypoints and refusal of nonfixture qualification. The fresh Linux fixture checks actual sealed API configuration using private temporary copies: valid deliveries pass, shared-readable and hard-linked copies fail, no installed credential changes and no private values are emitted. Existing TLS/CA-only trust, cache and broker recovery, schema/account/adoption/HTTPS, scientific/metadata and browser checks remain required under unchanged budgets.

D07, complete secret lifecycle, upgrades/rollback, production recovery, expert isolation and release/customer gates remain open. PR and separate main qualification are recorded independently.
