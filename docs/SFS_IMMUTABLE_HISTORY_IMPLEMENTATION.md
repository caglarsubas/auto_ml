# Operation-bound SFS history (P57)

SFS history previously derived archive names from the current file count and a timestamp with second precision, wrote directly to the destination, and continued successfully after archive errors. Concurrent publication could collide; retrying the same operation created another record, and successful live completion did not prove history had been retained.

New records use the accepted canonical operation UUID as their stable archive identity. A synchronized private staging file is linked atomically to an absent destination on the supported local Linux filesystem. Publication never replaces an existing archive. Identical evidence retries reuse the same bytes, inode and timestamp; changed, malformed or unreadable existing evidence blocks publication. A concurrent identical publication reconciles the winner instead of creating another entry. A retry after directory-sync uncertainty synchronizes the existing entry without rewriting it. This is application-enforced immutability, not a cryptographic signature or protection from privileged filesystem edits.

Non-stopped search outcomes, including failures, must be archived before the current result is replaced and live completion is exposed. Archive failure retains the preceding checkpoint and reports the correlated `history_evidence_write` diagnostic. A process loss then exposes that checkpoint as interrupted, without inventing a missing failure or automatically resuming. Gracefully stopped searches retain their existing checkpoint/resume semantics. A successful archive followed by a failed current-result save can leave archived search evidence alongside a live publication error: the archive records the search, not successful handoff, adoption, independent approval or deployment. Models, database records and filesystem pointers still have separate publication boundaries.

Legacy archives remain unchanged and inspectable. History lists recent files by filesystem modification time, rather than ordering UUID filenames as if they encoded time. New history rows expose their operation ID and recorded archive time to the existing browser list. The legacy numeric index is not assigned to new records; operation identity governs them. Hidden staging files are excluded. This does not qualify distributed SFS ownership, a full disaster-recovery workflow, arbitrary network filesystems or power-loss hardware.

Thirteen new regression cases cover stable retries and changed evidence, identical and distinct concurrent publications, link failure, directory-sync recovery, invalid identities, malformed existing evidence, background archive-before-completion/error behavior, and legacy history/order. The earlier final-save regression continues to inject a final-save serialization fault after a valid archive. Scientific fixtures and all timeout/retry/coverage/skip gates remain unchanged.
