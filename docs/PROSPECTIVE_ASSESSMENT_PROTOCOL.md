# Prospective protected assessment

D03-T01 defines first-use confirmation for the existing native numeric binary
classification and regression workflows. It uses the same sealed outcome
storage, independent adoption, development-only search, and bounded scoring
path as reviewed native assessment. The rest of the assessment surface
continues to produce exploratory evidence.

## Freeze and assess

1. Train with declared out-of-time validation and explicit prediction and
   outcome-end columns. A developer proposes the exact frozen training result,
   prediction contract, objective, and export. An independent reviewer accepts
   the proposal before the first held-out prediction date.
2. After outcomes mature, the same reviewer seals a separate CSV in the
   protected workspace. To request prospective assessment, the reviewer attests
   independent external custody and first use, and records their rationale.
   The server binds that assertion and the complete temporal window to the exact
   input bytes, adoption, actor, and independent approval. The as-of date must
   fall between the last outcome-end timestamp and the current time.
3. Review and submit the exact plan. It includes the frozen candidate, source,
   runtime, budgets, protocol version, and outcome window. Custody and preview
   record preparation only. The worker commits an attributable outcome-access
   reservation before reading labels. It verifies the sealed bytes, maturity,
   development separation and any declared entity constraint. It scores the
   frozen candidate using predictors only. Thresholds, costs, model state, and
   development preparation stay fixed through assessment.
4. Inspect the published classification and reason. A completed first use under
   this protocol can be confirmatory for the exact assessment. The result and
   common outcome-access receipt publish in one fenced transaction. A cancelled
   or superseded worker cannot publish confirmation.

The operator-managed profile relies on the reviewer's external custody and
first-use assertion. The application checks its own timestamps, frozen versions,
partition constraints, authority and access records. It cannot independently
observe earlier external use or authenticate external source provenance.

## Reuse and development boundaries

Started, failed, interrupted and completed attempts count as access. An exact
input match or an overlapping prediction-to-outcome window with recorded access
in the project yields exploratory evidence with a reason. Earlier unclassified
access in the project also withholds first-use confirmation. The conservative
overlap rule covers reordered or substituted rows with intersecting windows
within the project. A retry of the same completed job returns its original
receipt. A new assessment request consumes a separate access and cannot earn
a second confirmation of the same window.

Protected storage is absent from generic dataset, media, artifact, scoring and
MCP selectors. Governed upload and native CSV and legacy job preparation reject
known byte-identical prospective inputs before decoding them as development
data. Modified external copies require independent provenance. Historical
assessments and seals without the prospective attestation remain exploratory.
The protocol does not grant production-use approval or advance package review.
Full invalidation and exception adjudication across derived evidence belong to
D03-T02 and D09-T02.

## Operator checks

The reviewer workspace exposes an explicit first-use option and the exact
plan. A missing temporal declaration, approval after the window begins, or
unmatured outcomes returns an actionable refusal code. Result details include
the outcome-access ID and confirmation decision. Retain the adoption,
sealed-input, job and audit receipts for independent review.
