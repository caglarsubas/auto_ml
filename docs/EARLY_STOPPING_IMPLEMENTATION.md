# P09 — Declared native early stopping and scoring rounds

Native selection and tuning ranked the accepted metric while their fitters still stopped on AUC/RMSE. Initial training also used algorithm-specific fixed criteria. This could select different model rounds from those implied by the declaration, reject a usable loss on single-class validation data, or hide an undefined declared criterion.

New governed booster fits bind a primitive metric specification to the accepted prediction contract. Initial training, development folds, feature-selection screening/CV/refits, tuning trials/curves/winner refits, accepted candidates and on-demand selected-feature diagnostics use that specification. Candidate publication rejects a missing or changed fit metric before staging/adoption. Historical artifacts remain inspectable; an old fit cannot become newly qualified by adding a declaration after fitting.

Trusted callbacks use the shared development metric definitions. Binary objectives include ROC-AUC, average precision (PR-AUC), log loss, Brier score, expected cost, accuracy, F1, precision, recall and KS. Regression uses R², RMSE, MAE or MSE. Initial multiclass training preserves weighted one-vs-rest ROC-AUC, weighted F1, accuracy and log loss; multiclass selection/tuning remain blocked. Class ordering and positive-label meaning come from the existing accepted contract. Threshold metrics use 0.5, cost is per observation, and validation metrics are unweighted even when the training loss uses class weights.

An undefined required criterion stops before native fitting, with an error to revise the population/split or explicitly disable early stopping. For enabled stopping, the criterion must be available in both training and validation because CatBoost also evaluates its training partition. Available binary losses can use single-class validation; discrimination metrics require every declared class. Missing-class training remains blocked. Zero-round governed fits are explicitly unsupported.

Disabling governed early stopping fits without supplying validation data to the native learner and records that those labels were not used by the fitter. CatBoost no longer implicitly shrinks to a validation-selected model in that mode. Its first best iteration is correctly recorded as zero rather than replaced by the maximum round budget. LightGBM records its actual trained rounds when splitting stops early. Saved models preserve the selected prediction rounds and batch scoring parity.

The native fit receipt retains the accepted metric/cost/direction/class specification and source digest, complete per-round validation values, selected score, selected prediction rounds, zero-based best iteration, native surrogate loss and validation use. The native libraries may round regression labels to float32; XGBoost's recorded callback history uses six decimal places. Independent reference checks use the corresponding numerical tolerances. This precision is recorded, not a universal statistical acceptance threshold.

The business metric selects model rounds; native logistic/multiclass/squared-error losses remain the recorded fitter surrogates. This packet does not claim that a gradient directly optimizes a nondifferentiable business score. Existing fold-local preparation, class-weight policy, protected final outcomes, immutable candidate manifests and scoring replay are reused. Training evidence stays inside the existing expandable Details panel, with the declared criterion and surrogate loss explained separately.

Callback integration follows the official [XGBoost custom-metric interface](https://xgboost.readthedocs.io/en/release_2.1.0/tutorials/custom_metric_obj.html), [LightGBM evaluation interface](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.train.html) and [CatBoost metric interface](https://catboost.ai/docs/en/concepts/python-usages-examples#user-defined-metric-for-overfitting-detector-and-best-model-selection). These are trusted built-in implementations, not a new user-code execution boundary. CatBoost emits a warning that its Python callback cannot be JIT-optimized; capacity profiling remains open.

This is exploratory development evidence: stopping, selection, calibration and post-selection CV still reuse development data. It is not nested validation, a protected confirmatory protocol, independent reproduction, authenticated proof of fit, or customer acceptance. Legacy unbound fit paths remain explicitly unverified. Durable concurrent jobs, project roles/data egress, qualified expert isolation, private production recovery, independent review and D18–D26 agentic capabilities remain open. No outcome, milestone or release gate is closed by P09.

Qualification is recorded separately in the canonical ledger. Exact-head PR CI, merged-main CI, deployment and customer acceptance are separate claims.
