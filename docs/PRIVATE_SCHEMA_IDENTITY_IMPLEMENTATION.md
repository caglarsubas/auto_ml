# Declared metadata identity generation (P101)

A lost identity generator leaves the declared integer storage type, modifier,
nullability and non-generated-expression flag intact. An owned PostgreSQL probe
removes identity from `auth_user.id`; the predecessor admits startup while an
ordinary ORM insert fails. The new check returns `job_schema_invalid` before
broker/cache access without changing schema, sequences, data or migration history.

The contract derives identity from the sealed migration graph's **local** field.
The selected Django 5.2 PostgreSQL backend emits `GENERATED BY DEFAULT AS IDENTITY`
for `AutoField`, `BigAutoField` and `SmallAutoField`. Required auto keys must have
`pg_attribute.attidentity = 'd'`; ordinary fields must have an empty flag. A foreign
key to an auto key remains ordinary. A manual integer primary key also remains
ordinary. Replacing BY DEFAULT with ALWAYS is incompatible because ordinary
explicit-key inserts would fail. Older serial storage is not silently inferred
to satisfy this sealed profile; admitting another storage mode requires a versioned
compatibility decision and qualification.

The existing single catalog-only query compares the flag with the contract,
using `pg_catalog` JSON operators and the built-in internal `"char"` type/equality
operator. The response remains four fields with the table list as the first
parameter. Visibility, relation kind, storage types/modifiers, nullability and
non-generated storage checks retain their meaning and startup order. Extra
columns retain their existing policy, including extra identity columns.

Twenty-six new API/command cases cover lost or ALWAYS identity on auth keys,
auth through-table keys, migration recorder keys and bigint membership keys;
unexpected identity on manual smallint keys, foreign keys and attempt counters;
and healthy implicit/explicit inserts, ordinary foreign-key and manual-key writes,
plus extra columns. Native tests execute transactional PostgreSQL DDL. Reference
tests supply explicit denials and ordinary extra columns without emulating native
identity semantics. Original rows and migration history survive rollback. All
twenty-two predecessor denials fail while four healthy controls pass; no fixture
SQL errors are treated as evidence of the production defect.

Focused native checks pass 597 cases and reference/adoption checks pass 697.
Full local reference tests pass 4,167 cases with six existing skips under unchanged
limits. Local qualification results are retained in
[P101 source qualification](evidence/p101-qualification-2026-10-18.json).
Existing tests, fixtures, assertions, scientific workloads, execution limits,
coverage/skip/retry gates and dependencies are unchanged.

The separate ordinary NOCREATEDB probe runs actual history, write-mode, schema,
permissions and row-security checks on the predecessor. Fixed startup stops at
the schema guard before later guards and broker access. Initial TLS attestation
and broker connectivity are explicit response fixtures over an owned plaintext
connection. The deliberate direct ORM insert establishes the physical mismatch;
it is not verified transport, a full controller admission or an endpoint bypass.
Rollback restores the generator and a normal insert succeeds. No customer
installation is modified.

This is a selected-startup observation. It does not establish sequence state,
sequence ACLs, defaults, other constraints, collations, complete write availability,
full schema/data equivalence or later-state fencing. All six exact-commit checks,
complete private/native reports and independent merged-main qualification remain
required; full lifecycle/restore, release and customer gates remain open. D07
remains in progress.
