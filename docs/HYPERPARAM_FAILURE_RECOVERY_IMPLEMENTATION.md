# Honest tuning failures and atomic results (P58)

Hyperparameter status previously inferred completion when recorded status was absent or JSON reading failed. Persisted refit/search errors lost their diagnostic in the status endpoint after process-local progress disappeared. Direct result writes could expose partial JSON or truncate the preceding record before a storage failure.

Tuning status and results now share strict recorded-state parsing with SFS while retaining operation-specific reason codes and unchanged SFS contracts. Missing, unknown, contradictory, duplicate-key, nonfinite and malformed-list evidence is unavailable with HTTP 503 and no completion claim. An absent file remains not started/not found. Saved running evidence without a local owner is interrupted; live progress takes precedence. Readers preserve saved bytes and error/operation/duration metadata.

Accepted tuning requests carry a new operation ID. Actual swallowed search exceptions, winning refit/publication exceptions and final-save errors retain their stage, original execution identity and bounded trace frames. Structured service failure logs omit exception values, source lines, locals, rows and parameter values. Authorized results retain the actionable error. If error-record persistence also fails, live progress preserves the original failure plus a separate storage failure. A returned nonterminal or missing search state cannot become completed.

Result/error saving reuses the qualified strict-JSON atomic writer: synchronize private same-directory staging, replace the pointer, and synchronize the directory. Final-save failure does not trigger a second replacement that could erase previous evidence. Post-replacement directory-sync uncertainty may leave complete new bytes visible while live saving reports an error. The browser tuning poll uses the existing failure attachment helper with its unchanged 30-second budget and now requires the accepted operation ID as well as completed status. An older completed record cannot satisfy the newer attempt. The snapshot retains operation and storage-failure fields.

This is recorded-state and publication hardening. Tuning remains a process-local thread service. It does not create a durable operation journal or complete tuning history: if the final save fails and the process is then lost, a preceding saved record may remain available under its own operation ID; that record is not evidence of the newer attempt. No failure is reconstructed as certainty, and record shape does not prove independent review, authenticity, adoption or deployment. Legacy model-projection publication, distributed ownership, comprehensive restore and release/customer gates remain open.

Twenty-eight new regression cases cover both readers, live precedence/absence, saved valid states, actual swallowed native exceptions, search/refit/publication/final-write failures, secondary persistence failure and unsupported terminal results. Existing scientific tuning/SFS cases, reference metrics, partitions and timeout/retry/skip/coverage budgets are unchanged.
