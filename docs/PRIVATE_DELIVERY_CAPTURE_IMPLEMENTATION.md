# Consistent installation delivery capture (P53)

Both installation delivery readers now compare repeated bounded bytes and full descriptor metadata, including ownership, permissions and link count, before accepting captured inputs. Application delivery now checks each file's no-ACL contract before reading as well. All three routes — application delivery, dependency delivery and prepared application secrets — recheck ACL custody after reading. Previously the application reader could accept a file ACL, and both readers could accept changed bytes or custody when timestamp precision concealed the change.

Absolute paths, pinned ancestors/groups, strict members, regular single-link files, exact UID/GID/modes, original size limits and application value validation remain. Publishing still consumes the captured bytes through existing immutable/no-replace behavior; no credential is rotated, installed file changed or service recreated by these checks. Public certificate contents are captured here; certificate/hostname/key verification remains a separate existing initialization requirement.

Twenty-nine new cases cover exact bytes on all three routes, eighteen inter-read faults with coarse timestamps, initial ACL refusal and qualification scope. Nineteen cases fail against the preceding readers. Unit UID/GID/ACL faults are simulated. The isolated Linux component changes real UID/GID, mode, bytes and link count and installs zero-extra-access ACLs on temporary synthetic copies. It verifies all three routes without modifying installation inputs. Its owned ACL-capable volume and namespace are removed afterward; read-only source, disabled networking and bounded resources apply. CHOWN/FOWNER/DAC_OVERRIDE capabilities serve only these owned fixture copies. This component is not the complete host installation.

Fresh Linux CI repeats these delivery faults beside its owned fixture after adoption, alongside the preceding stored-reader, selected CA/TLS, authentication, recovery, schema/account, image and cleanup checks. It emits status only, never captured values. The application-copy values remain subject to the real validation function; they are synthetic shape fixtures, not certificate-trust evidence.

Consistency is observed during each file's capture. It is not an atomic snapshot across files or a guarantee against arbitrary authorized writers who change and restore inputs between observations. Trusted directory/ACL custody and existing controller locking remain necessary. Complete secret lifecycle, upgrade/rollback, production recovery, expert isolation and release/customer qualification remain open.
