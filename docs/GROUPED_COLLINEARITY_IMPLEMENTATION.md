# P28 — Grouped training-input dependence

Updated 11 October 2026. This packet extends the immutable P15 numeric diagnostic after merged [PR #117](https://github.com/caglarsubas/auto_ml/pull/117). It partially advances D04/D05/D06/D12 in the [canonical ledger](product-roadmap.json). Paired uncertainty, complete outcomes and every release/customer gate remain open.

Native initial training and candidate publication now record a separate `centered_group_subspace_gvif_v1` report. Numeric VIF retains its existing method and excludes category-derived outputs. The new calculation describes dependence between selected training-input groups, without labels, validation rows or final outcomes. It does not estimate fitted booster coefficient uncertainty or feature importance.

## Representation and method

Label, ordinal and native category values are treated as nominal partitions. Arbitrarily changing category codes cannot change the diagnostic subspace. Missing values form an observed level. Manual grouping describes the observed merged partition, not the original categories. One-hot groups come from exact encoding-provenance column lists, without prefix matching, and use only outputs selected in this execution. A candidate omitting a group does not inherit its parent's basis. Unused levels and within-group redundant contrasts are removed through numerical rank reduction; constant groups retain a zero-dimensional state.

Frequency/target-encoded values cannot reliably recover original category membership. These groups block the entire grouped calculation, with the recorded reason, instead of silently excluding them from the conditioning set. Invalid/overlapping provenance, unsupported nonnumeric predictors and invalid one-hot inputs also block calculation. Numeric predictors use the existing training-only mean imputation, with counts/means retained. Numeric constants do not contribute a subspace. No sampling or outcome-dependent imputation occurs.

Each eligible group's centered and scaled inputs produce an orthonormal basis by SVD. Basis rank uses `8 × machine epsilon × max(input dimensions) × largest singular value`. For each group, project its basis off the joint span of the other groups, allowing redundancies within that conditioning span. If residual singular values are `sᵢ`, `log(GVIF) = −2 × Σ log(sᵢ)` and the adjusted value is `exp(log(GVIF)/(2 × df))`, where `df` is the target subspace rank. For `df = 1`, GVIF equals the corresponding numeric VIF when the conditioning span matches; adjusted GVIF is its square root. Numeric-only VIF and a numeric group's mixed-group GVIF can differ because their conditioning sets differ.

This is the unweighted, centered design-subspace calculation described by [Fox and Monette (1992)](https://doi.org/10.1080/01621459.1992.10475190). The [car reference](https://cran.r-project.org/web/packages/car/refman/car.html#vif) documents coding invariance when term subspaces are preserved, dimensional adjustment, and the limits of transferring a design-matrix diagnostic to other fitted models. DeclarAI applies that geometry descriptively to the recorded input representation; it does not claim GLM, weighted-model or booster coefficient inference. Interactions and uncertainty estimates are outside this packet.

A residual singular value at or below `8 × machine epsilon × max(rows, joint basis width)` reports unbounded/perfect-or-numerically-indistinguishable dependence with null numeric values. This is a numerical tolerance, not a population hypothesis test. Conditioning rank, dimensions and sample saturation are recorded. Raw GVIF overflow retains its finite log and adjusted value separately; solver failure has an unavailable state. No fixed significance, GVIF or removal threshold is introduced.

## Immutable evidence and access

`diagnostics/collinearity.json` contains the additive grouped report and `diagnostics/grouped_collinearity.npz` retains float64 bases and group slices under the existing execution manifest. The files are native arrays/JSON; grouped inspection never deserializes fitted Python state or final outcomes. SHA-256 is corruption detection relative to the trusted controller, not an independent authenticity signature. These training-derived arrays remain subject to installation storage/egress policy.

`POST /api/modeling/vif-detail/` accepts `diagnostic: "grouped"` with exact `file_id`, `execution_id` and group `feature`. The default remains numeric. Grouped inspection verifies the manifest, method/identity, dimensions, layout, non-overlapping provenance, archive allocation, centering and within-group orthonormality; it replays and checks the recorded metrics. Historical executions without the new artifacts receive a refit error, not fabricated provenance. Both inspection modes are read operations for active developer/reviewer/admin project members. Revoked access is denied before reading, and the existing response authority recheck remains in force. Session authentication and CSRF remain required.

The grouped budget is independently bounded at 100 expanded input columns, 250,000 training rows and `rows × expanded columns³ ≤ 100,000,000`. Category indicators are allocated only after the budget passes. Exceeded budgets retain explicit unavailable group states and do not invalidate training or trim predictors. Archive entry sizes are checked against recorded dimensions before loading. These are engineering limits, not a deployment capacity promise.

## User workflow and qualification

The modeling workspace exposes an expandable grouped table with execution, training rows, dimensions, raw/adjusted GVIF, states, recorded inputs and limitations. Keyboard expansion and real native inspection are included in the existing governed browser workflow. Unavailable provenance and compute-budget explanations identify affected predictors. Assistant context carries the exact method, execution, representation and states; switching executions clears stale grouped context. The assistant's legacy universal VIF cutoff is removed.

Historical artifacts are preserved.
