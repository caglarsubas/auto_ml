# Adoption receipt readiness — P39

The P38 controller could observe all four services running, wait for valid HTTPS, then publish the earlier service snapshot. A worker or dispatcher paused/stopped or replaced during that interval could leave a successful receipt containing stale evidence. P39 samples the complete exact service profiles again after HTTPS and before receipt publication.

Both startup and final snapshots require exactly API, worker, dispatcher and ingress, with their existing image/plan/initialization/profile bindings, environment, mounts, limits, isolation and network/port controls. `Running` must be true and `Paused`, `Restarting` and `Dead` must explicitly be false; missing or non-boolean states fail. The final container IDs must match the initial snapshot. The final dependency/network/socket membership is rechecked against those same IDs. Failure emits no successful adoption receipt and never repairs, pauses, unpauses, stops or replaces an application.

The command and trust inputs remain [P38 adoption](PRIVATE_INSTALLATION_ADOPT_IMPLEMENTATION.md). A successful receipt adds `post_https_service_state: verified`. This is a sampled startup result, not a future health/capacity guarantee, a claim that every service was atomically observed at one instant, or model-use/installation/release approval. Inspect a blocked service and its bound profile before retrying; incompatible versions still require a reviewed upgrade workflow.

Qualification reproduces the missing paused-worker rejection against the preceding merged source, then checks final missing/duplicate/foreign services, stopped/paused/restarting/dead/unknown state, profile changes, replacement identity and changed dependency evidence. The owned Linux acceptance fixture performs valid real HTTPS and injects an actual Docker pause of its bound worker. Adoption must reject the final state while preserving all four IDs and the paused state; only the fixture explicitly unpauses its own injected fault. Normal adoption, retry, earlier CA/profile/role faults and owned cleanup remain required. Host runtime code does not enter the API image; its 196 sealed runtime sources remain unchanged. All existing six CI jobs and scientific, timeout, coverage, skip and browser retry budgets remain.

[P39 source qualification](evidence/p39-qualification-2026-10-12.json) records local checks; final exact-head CI and merge receipts are bound on the PR. D07 stays in progress. Dependency provisioning/hardening, encrypted storage/capacity, authenticated supply, upgrades/rollback, production recovery, expert isolation and all release/value/customer gates remain open.
